# Development

## New Host

Clone the repository and read [sharing.md](sharing.md). Restore config.toml
privately or copy config.toml.example and fill it locally. Do not print it.

```sh
cargo install espup
espup install
cargo install espflash ldproxy
```

Load the environment generated by espup for the installed toolchain.
On Linux/macOS this is typically ~/export-esp.sh; on Windows inspect the
generated setup and installed toolchain paths. Do not copy another user's
absolute paths. If needed, set LIBCLANG_PATH and PATH to the installed ESP
clang and Xtensa binaries.

Use separate short build directories for R2/S3 on Windows to avoid ESP-IDF
path-length problems. C:\t and C:\ts3 are examples, not shared requirements.

## Checks

```sh
cargo fmt --all -- --check
cargo clippy --no-default-features --features testing --all-targets -- -D warnings
cargo test --no-default-features --features testing
```

For a Windows linker failure without a useful diagnostic, retry tests with
`cargo test -j 1 --no-default-features --features testing`. Record persistent
failures instead of treating a successful lint run as a successful test run.

Parser fuzz smoke (requires cargo-fuzz, nightly, Linux/macOS; historical Windows
libFuzzer DLL issue):

```sh
cargo +nightly fuzz run pdu_decode -- -max_total_time=60
cargo +nightly fuzz run urc_parse -- -max_total_time=60
cargo +nightly fuzz run command_parse -- -max_total_time=60
```

## Build

Choose pins and target from [hardware.md](hardware.md). R2:

```sh
cargo +esp build --release --target xtensa-esp32-espidf
```

S3 on PowerShell:

```powershell
$env:ESP_IDF_SDKCONFIG_DEFAULTS = (Resolve-Path sdkconfig.esp32s3.defaults).Path
$env:SMSGATE_FLASH_LAYOUT = '16m'
$env:CARGO_TARGET_DIR = 'C:\ts3'
cargo +esp build --release --target xtensa-esp32s3-espidf
```

When switching back to R2 explicitly select sdkconfig.defaults, layout 4m,
the R2 target and its build directory; avoid stale environment overrides.
[.cargo/config.toml](../.cargo/config.toml) resolves the default SDK path using
Cargo's relative=true setting, providing the absolute path ESP-IDF needs.

OTA app image generation is provided by
[PowerShell](../tools/build-ota-images.ps1) and
[shell](../tools/build-ota-images.sh) scripts. See [operations.md](operations.md).

## CI

[ci.yml](../.github/workflows/ci.yml) runs host formatting, Clippy, tests and
partition validation on main pushes and pull requests.
There is currently no tracked nightly release or firmware-build workflow.
A green host CI run does not establish a working flashed device.
